# ЕМИР ЖКХ

Новая версия системы: фронт на React и TypeScript, бек на ASP.NET Core 10.

## Запуск для разработки

Нужны .NET 10, Node.js 20 и PostgreSQL 17 (`brew install postgresql@17`).

База, адрес `localhost:5433`. Один раз создайте кластер в папке проекта. Пароль `emir-dev-local` только для разработки, он записан в `appsettings.Development.json`:

```bash
printf 'emir-dev-local' > /tmp/emir-pw
LC_ALL=en_US.UTF-8 /opt/homebrew/opt/postgresql@17/bin/initdb -D backend/.pgdata -U emir --pwfile=/tmp/emir-pw --auth=scram-sha-256 -E UTF8 --locale=en_US.UTF-8
rm /tmp/emir-pw
printf "listen_addresses = 'localhost'\nport = 5433\nunix_socket_directories = '/tmp'\n" >> backend/.pgdata/postgresql.conf
```

Затем запускайте сервер базы и держите его включённым, пока работаете:

```bash
LC_ALL=en_US.UTF-8 /opt/homebrew/opt/postgresql@17/bin/postgres -D backend/.pgdata
```

Бек, адрес `http://localhost:5080`. При запуске сам создаёт базу `emir_dev` и применяет миграции:

```bash
ASPNETCORE_ENVIRONMENT=Development dotnet run --no-launch-profile --project backend/Emir.Api --urls http://localhost:5080
```

Фронт, адрес `http://localhost:5173`:

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

Тестовые учётные записи создаются только не в боевой среде. Пароль задан в `backend/Emir.Api/appsettings.Development.json`, поле `Seed:DemoPassword`.

| Логин | Роль |
|---|---|
| `kassa1` | Кассир |
| `oper1` | Абонентский отдел |
| `buh1` | Бухгалтер |
| `admin` | Администратор |

Все абоненты и суммы в тестовой базе вымышлены. Чтобы вернуть её к началу, остановите бек, выполните команду ниже и запустите бек снова:

```bash
PGPASSWORD=emir-dev-local /opt/homebrew/opt/postgresql@17/bin/dropdb -h localhost -p 5433 -U emir emir_dev
```

## Тесты

Серверным тестам нужен запущенный PostgreSQL. Каждый набор создаёт свою временную базу и удаляет её. Другой сервер можно указать через `EMIR_TEST_POSTGRES`.

```bash
dotnet test backend
npm --prefix frontend test
```

## Изменение схемы базы

```bash
backend/ef.sh migrations add ИмяИзменения
```

Запускайте `dotnet ef` только через этот скрипт. На macOS инструмент оставляет в проекте папку с именем `bin\Debug`, из-за которой падает сборка с нуля. Скрипт её удаляет.

## Запуск в Docker

Нужен Docker Desktop или OrbStack. Всё поднимается одной командой, сборка идёт внутри контейнеров:

```bash
docker compose up -d --build
```

Сайт открывается на http://localhost:8080. База и сервер наружу не открыты. Пустая база создаётся сама, вход появится после команды `create-admin` или разворачивания дампа:

```bash
EMIR_DUMPS=~/emir-migration/dumps EMIR_ADMIN_PASSWORD='не короче 12 символов' deploy/restore-dump.sh имя.dump
```

Скрипт удаляет всё в базе контейнера и разворачивает дамп. Чтобы сайт был доступен с других компьютеров своей сети, запустите с `EMIR_BIND=0.0.0.0`. Это открывает данные всем в сети, поэтому только в доверенной сети и не через публичные туннели.

## Боевая установка

В боевой среде приложение не меняет схему само и не запускается, если база отстаёт от миграций. Тестовые данные там не создаются. Настройки задаются переменными окружения:

| Переменная | Назначение |
|---|---|
| `ConnectionStrings__Default` | Подключение к PostgreSQL |
| `DataProtection__KeysPath` | Папка ключей cookie, чтобы вход не сбрасывался при перезапуске |

Порядок первого запуска, команды выполняются для собранного приложения:

```bash
dotnet Emir.Api.dll migrate
```

```bash
EMIR_ADMIN_PASSWORD='не короче 12 символов' dotnet Emir.Api.dll create-admin логин "Имя Фамилия"
```

```bash
dotnet Emir.Api.dll start-period 2027-01
```

SQL-скрипт миграций для администратора базы:

```bash
backend/ef.sh migrations script --idempotent
```

Резервная копия и проверка, что копия читается:

```bash
pg_dump -h адрес -U пользователь -Fc -f emir.dump имя_базы
```

```bash
pg_restore -l emir.dump
```

## Что работает на сервере

- Вход по cookie, ограничение попыток, проверка ролей на каждом запросе.
- Абоненты: список, регистрация, смена адреса, добавление услуги.
- Адреса из справочников, как в старой системе: населённый пункт из «Городов», улица из «Улиц» этого пункта, дом из «Домов» этой улицы, квартира руками. Новую улицу или дом можно завести прямо из формы адреса (кнопки «Новая» и «Новый», запись в журнал). Переименование улицы или дома в справочнике меняет адрес абонентов, удалить используемый адрес нельзя. Если справочников адресов нет, они собираются из адресов абонентов при запуске.
- Касса: оплата с защитой от двойной отправки, возврат с причиной, лента смены.
- Показания: повторный ввод начисляет только разницу.
- Корректировки: сумму отмены платежа определяет сервер, причина обязательна.
- Обмен: загрузка CSV и TXT в формате `лицевой счёт;сумма`, проверка строк, однократное проведение.
- Отчёты: должники и касса считаются по данным, есть выгрузка CSV.
- Журнал действий по всем операциям с деньгами.
- История тарифов: цена тарифа и условия услуги действуют с указанного месяца. Начисление считается по ценам своего месяца и хранит использованную цену. Прошлые месяцы менять нельзя, открытый можно только до первых начислений или показаний.
- Расчётные месяцы: закрытие, открытие следующего, исправление последнего закрытого. Месяц открывается на исправление с причиной, показывается разница по каждой услуге, после подтверждения она проводится в долг или переплату. Старые значения остаются в `ChargeRevisions` и журнале абонента.
- Сверки месяца: расхождения начислений с расчётом, услуги без начисления, резкие изменения сумм, показания по неработающим услугам, чужой тариф в населённом пункте, дубли, переплата вместе с долгом, непроведённые реестры, изменения от перезакрытия. Только чтение, выгрузка в CSV.
- Документы по закрытому месяцу: квитанции физлицам, счета, акты и счета-фактуры юрлицам. Сквозная нумерация по годам, реквизиты организации как настройка, снимок данных в каждом документе, перевыпуск с номером исправления, пакетная печать из браузера. После перезакрытия документы помечаются устаревшими.
- Журнал денег `LedgerEntries`: каждое изменение долга и переплаты записывается автоматически при сохранении, изменение без указанной операции отклоняется, менять и удалять записи запрещает база. На нём строятся движение денег в карточке абонента, оборотная ведомость и сверка остатков с журналом.
- Сотрудники (раздел «Админ»): создание с временным паролем, смена роли, отключение, сброс пароля. Смена своего пароля в профиле. Сессия сверяется с базой при каждом запросе, поэтому отключение и смена пароля действуют сразу. После 5 неверных паролей вход блокируется на 15 минут (настройки `Auth:LockoutAttempts`, `Auth:LockoutMinutes`).
- Карточка абонента: площадь и жильцы с историей по месяцам, список проживающих, заметка, согласие на передачу данных, документ о праве собственности, телефон, цена и объём в списке услуг, справка о состоянии счёта.
- Льготники: категории, реестр с датами и живой отметкой «Должник», блок в карточке, загрузка файлом с предварительной проверкой, выгрузка ответа соцзащите. Льгота не меняет начисление, как и в старой системе. Форматы файлов предварительные, образцов от соцзащиты нет. Кассе раздел недоступен.
- Массовая отмена начислений открытого месяца: выбор услуг и абонентов, просмотр сумм, причина, подтверждение. Показания остаются, оплаченная часть становится переплатой, шаги месяца начинаются заново. Закрытый месяц меняется только перезакрытием.
- Загрузка показаний из файла: настраиваемые колонки и разделитель, UTF-8 и Windows-1251, проверка каждой строки до записи, большой расход записывается только по отдельному согласию, правила те же, что при ручном вводе.
- PostgreSQL и миграции. Денежные операции идут в транзакциях `Serializable`: при одновременном изменении одних данных один запрос получает ответ 409 с просьбой повторить операцию, деньги не теряются.

## Что ещё не реализовано

- **Сверка начислений и пени.** Формулы схем и пени сверены с исходным кодом старой системы (классы `GKH.Contract.Scheme.*`, `Penaltie.Control`), но не с реальными квитанциями. Цены тарифов в тестовой базе вымышленные. Схемам «Годовое распределение» (`HeatLost`) и «Ежемесячный объём по дому» (`MonthlyQuantityHouse`) пока не передаются нужные данные: распределение тепла по месяцам и потери тепла дома.
- **Начисление по среднему, НДС, данные домов для общедомовых счётчиков, открытие следующего месяца.**
- **Настоящий перенос данных.** Загрузчик готов, см. [docs/migration.md](docs/migration.md). Нужны файлы из старой системы и сверка соответствия полей.
- **Перезакрытие старых месяцев и пересчёт пени.** Исправить можно только последний закрытый месяц и только пока в следующем нет начислений и показаний. Для более ранних ошибок служат корректировки. Пени при перезакрытии не меняются.
- **История нормативов по заказу:** при перерасчёте берётся значение на момент начисления. Площадь и жильцы уже с историей.
- **Категории домов и норма теплопотребления** в карточке абонента.
- **Настоящие форматы обмена с соцзащитой** и история запросов и ответов: нужны образцы файлов.
- **Сверка оперативного и бухгалтерского остатка.** В новой системе один остаток, сверяется он с журналом денег. Разделение на два зависит от решения бухгалтера.
- **Автоматический повтор при конфликте.** Сейчас при ответе 409 кассир повторяет операцию сам.
- **Остальные отчёты и справочники:** они показывают сообщение, что появятся после переноса данных.
- **Документы:** формы не сверены с бухгалтером и не проверены юристом, в квитанции нет QR-кода и она не приведена к форме ЕПД. Нет счёта на предоплату, досрочного закрытия периода по договору, выгрузки в 1С и ЭДО. Порядок НДС (входит в сумму или сверху) нужно подтвердить.
- **Обмен:** форматы банков и 1С, ГИС ЖКХ, льготники. Сейчас поддержан только простой CSV.

## Перед боевым запуском

- Включить HTTPS: в боевой среде cookie всегда помечается `Secure`, по HTTP вход работать не будет.
- Настроить расписание резервных копий и проверить восстановление из копии.
- Паспорт абонента хранится зашифрованным (ASP.NET Data Protection), расшифровывает только просмотр администратора с записью в журнал. Ключи лежат в `DataProtection__KeysPath`: без резервной копии этой папки паспорта не прочитать.
