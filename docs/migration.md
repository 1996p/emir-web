# Перенос данных из старого ЕМИР

Перенос выполняется командой на сервере, где работает новая система. Файлы с персональными данными никуда не передаются, а в отчёт команды попадают только файл, строка, лицевой счёт и причина.

## Порядок

Сделайте резервную копию и заморозьте ввод в старой системе, чтобы остатки не менялись во время переноса.

1. Создать пустую базу и применить миграции:

   ```bash
   dotnet Emir.Api.dll migrate
   ```

2. Положить файлы в одну папку и выполнить пробный прогон. Он проверяет всё и ничего не записывает:

   ```bash
   dotnet Emir.Api.dll import-data /путь/к/папке 2026-11
   ```

3. Исправить ошибки и прочитать предупреждения. Повторять, пока ошибок не останется.

4. Загрузить. Записывается всё или ничего:

   ```bash
   dotnet Emir.Api.dll import-data /путь/к/папке 2026-11 --apply
   ```

5. Загрузить справочники старой системы (только для просмотра, деньги не затрагиваются, можно повторять):

   ```bash
   dotnet Emir.Api.dll import-references /путь/к/references.json
   ```

   Файл собирает `tools/old-emir/build_references.py` из скачанных списков.

6. Загрузить адресный справочник: населённые пункты, улицы и дома для выпадающих списков адреса. Команда только добавляет недостающее, ничего не удаляет; без `--apply` — пробный прогон:

   ```bash
   dotnet Emir.Api.dll import-addresses /путь/к/addresses.csv --apply
   ```

   Файл в формате `Населённый пункт;Улица;Дом[;…;ГИС ЖКХ;ФИАС]`, UTF-8. Его можно собрать из выгрузки базы старой системы (классы `Address.PCity`, `Address.PStreet`, `Address.PHouse`), см. раздел «Выгрузка базы старой системы».

7. Создать администратора:

   ```bash
   EMIR_ADMIN_PASSWORD='не короче 12 символов' dotnet Emir.Api.dll create-admin логин "Имя Фамилия"
   ```

7. Заполнить реквизиты организации, настроить нумерацию документов и открыть раздел «Сверки».

`2026-11` здесь первый расчётный месяц в новой системе. Для него начисления ещё не должны быть проведены.

## Формат файлов

CSV с первой строкой из названий колонок, разделитель `;`, кодировка UTF-8 или Windows-1251. Значения с `;` берутся в кавычки. Суммы в рублях, не больше двух знаков после запятой. Даты `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`. Месяцы `ГГГГ-ММ`. Жирным выделены обязательные колонки.

### tariffs.csv, обязательный

**id**, **name**, **scheme**, unit, service_norm, tariff_norm, penalty_enabled

`scheme` это название схемы начисления из старой системы, например `HeatHouseNorm` или `MeterApartment`. Полный список в `ChargeEngine.Schemes`.

### tariff_prices.csv, обязательный

**tariff_id**, **from_period**, **price**

История цен. Для цены, действовавшей с неизвестного момента, укажите `2000-01`.

### abonents.csv, обязательный

**account**, **kind** (`ФЛ` или `ЮЛ`), **name**, **street**, short_name, place, flat, phone, inn, area, residents, house_heat_norm, district, boiler, heat_chamber, house_category, wall_material, credit, note, consent (`да`, `нет` или пусто), ownership_document

`district`, `boiler`, `heat_chamber`, `house_category`, `wall_material` это сельсовет, котельная, тепловая камера, категория дома и материал стен для отчётов. В уже заполненной базе их можно обновить командой `update-abonent-attributes abonents.csv`, деньги она не трогает.

`house_heat_norm` это норма теплопотребления категории дома в Гкал на м² в месяц. Без неё схема `NormHouse` не начислит.

### services.csv, обязательный

**account**, **service_id**, **name**, **debt**, state, tariff_id, contract_norm, meter_number, meter_last_reading, meter_verified_until, meter_average, house_meter_id

`debt` это долг на начало первого месяца. Отрицательный долг переносится в переплату абонента, команда об этом предупреждает. Пени указываются отдельной услугой с `service_id` равным `penalty`.

### house_meters.csv и house_meter_readings.csv, для схемы `MeterHouse`

`house_meters.csv`: **id**, **street**, place, number, unit, unit_factor. `unit_factor` это сколько Гкал в единице показаний: для Гкал 1, для ГДж около 0,239.

`house_meter_readings.csv`: **meter_id**, **period**, **value**. Расход месяца это разница показаний, умноженная на `unit_factor`. Он делится по площади между работающими услугами, у которых в `services.csv` указан этот `house_meter_id`.

### charges.csv, нужен для пени

**account**, **service_id**, **period**, **amount**, volume, price

Начисления за прошлые месяцы. Пени считаются от месяца начисления, поэтому без этой истории пени на старые долги начисляться не будут.

### control.csv, настоятельно рекомендуется

**metric**, **value**. Показатели: `abonents`, `services`, `tariffs`, `charges`, `payments`, `total_debt`, `total_credit`.

Итоги из отчётов старой системы. Если они не совпадут с файлами, загрузка не пройдёт. Это главная проверка, что ничего не потерялось.

### payments.csv, необязательный

**account**, **date**, **source**, **amount**, cashier

История для просмотра. На остатки не влияет, они уже учтены в `services.csv`.

### residents.csv, необязательный

**account**, **name**, from_date, to_date

### beneficiaries.csv, необязательный

**account**, **full_name**, **category**, from_date, to_date, uuid

Категории льгот создаются по названиям из этого файла.

## Что не переносится

- Прошлые показания счётчиков: переносится только последнее.
- История площади и жильцов, состояний услуг: начинается с первого месяца.
- Журнал действий, выпущенные документы и их номера. Номера продолжаются через настройку нумерации.
- Сотрудники: создаются заново в разделе «Админ».

## Что нужно решить до настоящего переноса

- Откуда взять файлы: выгрузка администратора Caché или отчёты интерфейса. От этого зависит, какие поля доступны.
- Соответствие схем начисления и состояний услуг старой системы шаблону.
- Как считать `debt` в старой системе: баланс услуги может включать переплату с другим знаком.

## Выгрузка базы старой системы

Старая система работает на InterSystems Caché 2017. Её базу можно поднять локально в InterSystems IRIS Community (Docker) и читать напрямую, без разбора страниц сайта:

- код классов — экспорт в XML (`$system.OBJ.Export`), вместе с include-файлами (`*.inc`: `FastUtils`, `SYSTEM`, `CommonUtils`, `ERRORMESSAGE`), иначе классы не компилируются;
- данные — экспорт глобалей утилитой `^%GOF` (файл `.gof`).

Файлы нужно передавать **как двоичные**: архивом (zip) или копированием файла, но не через окно терминала, текстовый редактор или вставку текста. В выгрузке от 08.11.2026 оба файла пришли повреждёнными: каждый байт выше 127 был перекодирован в UTF-8 (обратимо), а сами файлы обрезаны — XML на шаблоне `ZENReport.template.AllDocs`, `.gof` на глобале `^BookKeeping.CashOrderD` (из 392 глобалей есть около 30 первых по алфавиту). Договоров, тарифов, показаний, журнала денег и настроек в ней нет.

Если весь экспорт не проходит целиком, выгружайте глобали частями (по пакетам: `Contract.*`, `GKH.*`, `Money.*`, `Reference.*` и так далее) и проверяйте размер файла до и после передачи.
